<objective>
Build the fixture sanitiser and the PII/secret scan that together keep personal data and tokens out of `evals/fixtures/**` (CI-05), plus the gitleaks config the CI secret-scan job uses.

Purpose: Qodo Merge has no path-ignore support and review bots cannot be relied on to inspect large fixture files, so this code is the only dependable gate against leaking cookies, tokens or personal data in saved page snapshots (and it must run before a fixture is ever pushed, since Qodo will read whatever is in the diff). Fixtures start arriving in Phase 3, so the gate must exist first.
Output: Tested pure modules, two CLIs behind the existing `pnpm sanitise:fixture` and `pnpm scan:fixtures` scripts, and `.gitleaks.toml`.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| live browser capture -> repo fixtures | Page snapshots may carry cookies, tokens and personalised data |
| CI logs | Scan output is visible to anyone with repo access |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-27 | Information disclosure | evals/fixtures/** | mitigate | sanitise-fixture is the only way in; scan blocks emails, phones, postcodes, JWTs, API keys, opaque tokens, cookie headers, ntfy topic and leftover scripts |
| T-01-28 | Information disclosure | scan output | mitigate | Findings carry only path, line, kind and a masked preview, never the matched value |
| T-01-29 | Tampering | scan gate silently passing | mitigate | `--self-test` plants every kind and fails if any is missed; CI runs it (plan 07) |
| T-01-30 | Information disclosure | committed test files | mitigate | Secret-shaped test data assembled at runtime so gitleaks stays clean without broad allowlists |
| T-01-31 | Denial of service | regex backtracking | mitigate | Non-greedy bounded patterns, line-by-line scanning; fixtures expected to be well under 1 MB |
