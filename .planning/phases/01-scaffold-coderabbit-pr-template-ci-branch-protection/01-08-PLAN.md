<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| local repo -> GitHub | Code and PR text become visible to collaborators and review apps |
| review tool (Qodo) -> code | Third-party services read the diff |
| Claude's gh token -> repo settings | Can change branch protection |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-39 | Information disclosure | PR body and evidence | mitigate | Evidence uses redacted log lines only; no .env content, keys or connection strings; secret-scan is green before the PR opens |
| T-01-40 | Elevation of privilege | branch protection change | mitigate | Applied only after the owner selects apply-protection; read back and reported |
| T-01-41 | Tampering | unreviewed merge | mitigate | Claude never merges or uses --admin; STOP checkpoint is blocking |
| T-01-42 | Information disclosure | code sent to Qodo | accept | Owner-chosen tools; the repo contains no secrets or personal data by design (scans enforce it) |
| T-01-43 | Denial of service | Qodo quota exhaustion | mitigate | One PR, no automatic re-review on push, at most one manual re-trigger; Qodo is not a required check |
</threat_model>
