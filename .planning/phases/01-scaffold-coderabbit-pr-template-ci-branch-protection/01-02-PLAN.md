<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| process env -> app | Secrets (Anthropic key, ntfy topic/token) enter via env |
| app -> PostHog (Phase 3 backend) | Event properties leave the machine; must carry no PII or page content |
| PostHog flags -> app | Remote flag values can switch sellers on or off |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-04 | Information disclosure | EnvValidationError message | mitigate | Message built from issue path + message only; test asserts a supplied secret value never appears |
| T-01-05 | Information disclosure | telemetry capture | mitigate | Strict zod schema per event, enum-only reasons, no free-text fields, unknown events dropped, enforced in the facade for every backend |
| T-01-06 | Information disclosure | captureException / span url | mitigate | Message truncated to 200 chars and stripUrlQueries removes query strings and fragments |
| T-01-07 | Denial of service | flush/shutdown | mitigate | Timeout race with unref'd timer, backend errors swallowed so analytics never blocks or crashes a run |
| T-01-08 | Tampering | PostHog flag override | accept | Owner-controlled PostHog project; worst case is a seller switched on/off; resolved map is logged at startup |
| T-01-09 | Information disclosure | .env.example | mitigate | Dummy values only (`sk-ant-replace-me`, `change-me-local-only`); the gitleaks scan in plan 07 runs over it |
</threat_model>
