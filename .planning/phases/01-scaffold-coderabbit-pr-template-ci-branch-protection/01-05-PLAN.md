<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Qodo Merge (third-party app) -> PR | Reads PR diffs of a private repo; posts comments |
| Renovate (third-party app) -> repo | Opens PRs that change dependencies |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-23 | Tampering | Renovate PRs | mitigate | Pinned versions (rangeStrategy pin), Actions pinned by digest, held-back majors, every Renovate PR runs full CI and gets no secrets (plan 07) |
| T-01-24 | Information disclosure | Qodo Merge reading private code and fixtures | accept | Owner chose and installs the app; path ignores are unsupported, so fixtures must already be sanitised before commit (plans 06, 07 enforce it); repo holds no secrets by design (gitleaks in plan 07) |
| T-01-25 | Repudiation | review outcomes | mitigate | PR template records Qodo outcomes in the PR description |
| T-01-26 | Elevation of privilege | review bots as merge gates | mitigate | Qodo is not a required check, so an outage or exhausted quota cannot block or approve merges |
</threat_model>
